## 使用规模与人口分析取舍（用户确认，2026-11-04）

系统面向受控使用者，不完全向大众开放，调用次数可控。容量规划以实际受控调用量为依据，不为假设中的公开高并发预先自建地理集群、分布式队列或批量全球数据管线。
优先使用适合小规模的现有服务，并设置应用级总量、并发、单次范围和费用上限；具体数值在实施规划中按实际需求确定，不虚构调用规模。
低调用量不自动代表可使用任意公共服务。公共/演示实例如条款允许实际用途且接受其可用性限制，可以显式配置用于受控轻量使用；不默认绑定、不绕过限制，保留手工/合法旧资料回退。专用托管或自建仅在实际质量、稳定性或额度不足时评估。

人口分析是可选能力，按实际价值与总成本取舍，不作为核心闭环或三个餐饮模板的必需前提：
- POP-01：已有合法行政区人口或用户资料的展示/引用，可在低成本且有实际用途时提供；标注年份、区域和来源，不说成门店可达范围人口。
- POP-02：自定义范围的网格人口汇总，降为低优先级；只有在资料获取、维护和误差解释成本合理时再做。
- POP-03：R5py 公交范围人口估算、复杂网格旅行时间计算或等时线转面后人口叠加，最低优先级，首批不做；若收益不足可不实现。
以上层级是本次约束下的规划建议，不代表已量化证明人口分析性价比低。评估需比较决策价值、资料/许可、一次性接入、持续更新、计算费用、等待时间、核实成本与不确定性；没有明确使用者或收益时保持停用。
不为人口分析单独引入 JVM/R5py、全国数据更新或额外基础设施。R5py 技术选型保留为条件备选，仅有独立且有价值的公交分析需求时重新评估。
不做人口分析不阻塞地址、周边设施、企业地点发现、基础交通与地理比较。已选择范围内的非人口分析可以完整完成；显式请求了人口却未取得时报告未启用/部分结果，不填零，也不冒称全主题完整。

## 选择
- 基础契约：Pydantic 2 与标准库；Shapely＋pyproj 作为可选 geometry。
- 网络适配：HTTPX；Photon 地址；ORS 路线/等时圈（新 HeiGIT 地址）；Overpass POI。
- 批量/统计：pyosmium 可选 PBF；GeoPandas＋pandas＋pyogrio；官方 Zensus/BKG 数据按用途使用。
- 时间：opening_hours_py 可选解析；公交引擎保留 R5py 技术路线；默认暂缓启用，不为人口分析单独引入其 JVM/JAR。GTFS 工具随实际公交需求选择。
- 调用方地图：MapLibre；已有 Leaflet 不强制迁移。
- 自有薄层：来源/质量/配置/模板/实体核实/比较快照，不重造地理算法。
- 暂不采用默认 PostGIS、H3、OSMnx；QGIS 仅人工 QA；不嵌入上游服务器或复制仓库。

## 选择边界
库/引擎确定不等于生产 endpoint/服务合同已确定。Photon 实例和瓦片提供者按具体使用权配置；受控轻量使用可显式评估符合条款的公共实例，不能偷偷依赖 demo；没有获准实例即未配置。
ORS 当前完整 ToS/配额本次抓取无正文，官方近期回复提供部分商用与 CC-BY-SA 依据，生产前必须核实全部条件。
不使用公共 Nominatim 联想；不使用已经移除的 OTP TravelTime API；R5py 等时线不等于可直接叠加的区域面。
Python 3.12 是首次验证目标；版本表是观察快照，不是已通过兼容测试的锁文件。

## 理由与替代
Photon 匹配地址联想需求；Pelias 留作多源地址质量不足时替换。
ORS 提供所需道路分析组合；Valhalla 留作自托管替代。
GeoPandas 路线保留离线统计，数据库非必要；PBF 保留可控批量数据路线。
R5py 的矩阵分析适合公交区域研究；OTP 适合其他行程服务而不是使用旧等时圈接口。
不承诺一个库能解决企业人数、购买力或实时人流资料缺失。

# ADR-0002：通用核心、可选行业配置与用途模板

日期：2026-11-04。
状态：核心方向由用户明确确认；设计审查补充随本次保存请求纳入规划基线。无实现或发布声明。
承接 [ADR-0001](ADR-0001-independent-shared-repository.md)，不改变独立共享仓库与既有交付原则。

## 背景
RestaurantTrafficDiagnosis、GastroPreisRadar 和选址产品需要共享地理事实，但经营解释不同。
完全餐饮专用会将某个业务假设写入公共能力；完全底层通用会让各调用方重复维护类别与组合查询。

## 决策
1. 核心保持行业无关，提供地点、范围、交通、设施、统计、证据与中立比较。
2. 单项查询无需行业参数。
3. 行业配置定义类别映射、主题、默认条件、展示分组及能力要求；不包含评分或经营推理。
4. 用途模板与行业配置分开标识、管理和版本化。模板组合能力并可引用配置。
5. 首先提供餐饮类别和周边环境、商户发现、地点比较三个模板。
6. 用餐饮、零售、教育验证通用性；不据此建设三个完整行业产品。
7. 默认条件可查看、可覆盖；每次保留有效条件、配置/模板版本及来源时间。
8. 数据不足明确报告，替代方案不得静默改变范围、分类、年份或分析含义。
9. 比较提供指标差异和可比性，不生成综合优劣或投资结论。
10. 业务系统负责案件、权限、持久化、交互界面、通知和业务判断。独立行业推理未来另行设计。

## 方案比较
| 方案 | 优点 | 代价 / 不采用理由 |
|---|---|---|
| 餐饮专用核心 | 初始调用直接 | 易把诊断/竞争规则绑定核心，妨碍不同餐饮产品复用 |
| 完全通用、调用方自行组合 | 地理边界纯粹 | 类别与模板重复维护，调用复杂 |
| 通用核心＋配置＋模板（采用） | 保持复用并提供易用入口 | 必须维护职责边界、版本与默认条件透明度 |

## 后果与约束
不会为所有潜在行业提前建设平台；只从实际使用场景抽取通用能力。
配置不等于所有地区都有数据，模板不保证所有主题成功。
行业分类不等于竞争判断，人口不等于需求，路网可达不等于安全/无障碍。
过去快照不随模板升级改变；可复现受输入保存权利约束。
不提供代码、字段定稿、基础设施或供应商选择；这些留给下一步实施规划。

# 最佳接入方案：开源能力与通用核心

日期：2026-11-04。状态：实施规划的技术选型基线；未实现、未部署、未运行集成验证。
依据：[逐项调研](../research/OPEN_SOURCE_SELECTION.md)、[版本核验](../research/OPEN_SOURCE_VERIFICATION_2026-11-04.md)、[功能设计](../design/FUNCTIONAL_DESIGN.md)。

## 1. 依赖边界

最小基础包：Pydantic＋标准库，提供地点/输入验证、结果契约、来源状态、配置和模板解析，不需要密钥/数据库/云账号。
可选依赖组（名称是建议，尚非可安装包）：
- geometry：Shapely＋pyproj。基础空间计算，不启动网络。
- providers：httpx。Photon、ORS、Overpass 的受控访问与归一化。
- statistics：GeoPandas＋pandas＋pyogrio，复用 geometry；仅统计使用者承担 GDAL 等依赖。
- temporal：opening_hours_py；时区可由调用方明确提供，不依赖推断。
- osm-import：pyosmium，离线区域文件处理。
- dedupe：RapidFuzz，可选候选排序，不决定合并。
- transit：R5py 和配套 JVM/JAR，隔离为重型运行环境，不能由默认 import 间接加载。
- 前端 MapLibre 留在消费者；QGIS 和 GTFS validator 是人工/数据准备工具。
- PostGIS、H3、OSMnx 不作为默认依赖，不复制第三方仓库或使用 submodule 包含服务器源码。

首个验证环境目标 Python 3.12。不要直接把调研时所有 latest 组成 lockfile；按选定版本实际解析、安装和测试后生成锁与软件物料清单。
普通 pip 安装与验证可在云端完成；本方案不要求使用用户个人电脑。

## 2. 稳定接口与隔离

下列是建议职责而非已定稿 API：
LocationResolver -> 地址候选/反查；CatchmentProvider -> 路网范围；
PlaceProvider -> 设施记录；StatisticsSource -> 有元数据的统计数据；
TransitAnalyzer -> 班次/旅行时间结果；Evidence/Quality -> 全部结果的共同说明。
手工输入、文件输入和远程 provider 共用结果契约，保留来源类型，不冒充相同可靠度。
公共对象以普通类型、明确字段和 GeoJSON 表达；不把第三方 DataFrame、HTTP response 或数据库对象作为必需契约。
内部可用 Shapely/GeoPandas，消费者不需要了解其索引和私有对象。

每次请求由以下信息组成：
- 已确认位置版本或区域、入口用途；
- 所需能力、类别、范围和时间/时区；
- 可选 profile_id/profile_version、template_id/template_version；
- 已解析的有效参数、调用方强制限制、数据使用目的和额度；
- 请求标识，不传客户姓名/案件原文给外部地图服务。

每次结果至少能表达：
status、data、warnings；位置/范围/时间/有效条件；
来源、资料参考时间、获取时间、方法版本、精度、缺失；
使用限制、归属说明、核实状态与复现所需版本。
这些字段在下一步合并进 V1 草案，不把此处说明当已实现 schema。

## 3. 各条数据通路

### A. 地址
输入校验 -> 选择已配置 Photon endpoint -> 有界查询 -> 解析候选 -> 保留来源/语言回退/精度 -> 调用方人工确认。
Photon 查询 q、bbox/countrycode、lang、limit 等由适配器按已核实服务器版本映射；位置 bias 不是硬地理边界。
取消过时联想请求、限制最小输入/查询频率，禁止把每次按键直接无限转发。
第三方候选不直接成为 confirmed location。地图链接仅白名单解析允许的 URL，重定向逐跳检查，不抓受限制页面。

### B. OSM 设施
通用类别 -> 来源标签映射 -> 有界 Overpass 查询或获准 PBF 快照 -> 统一原始记录 -> 几何筛选 -> 去重候选 -> 设施结果。
OSM id 必须带 node/way/relation 类型。原始几何和显示点分开，中心点不能当入口。
PBF 导入以最小区域文件开始，不每个请求下载全德国；记录提取边界和资料时间。
空数据可记录“本次无匹配”，不由此断言现实零设施。Overpass 返回 remark/截断/超时必须识别为部分或失败。
同一查询缓存键包括来源实例、数据版本（可得时）、类别映射版本、范围、时间与方法；私有补充资料不进入公共共享缓存。

### C. 几何和路线
每次声明 outbound（从地点出发）或 inbound（前往地点），另行声明 depart-at 或 arrive-by 时间语义；方向与时间不是同一参数。到店/到校研究必须明确选择 inbound，不能直接把从门店出发的等时圈称为顾客到达覆盖。道路单行和公交时刻会造成方向不对称。适配器不能支持要求时返回 unsupported；可以显式选择以周边点为 origins、门店为 destination 的矩阵估计，并标注采样方法，不能反转已有线或仅改标签。
直线几何通过本地 geometry；路网范围通过 ORS，二者结果类型和方法不同。
请求将内部秒/米明确映射到供应商单位，返回校验坐标、几何、范围与交通方式；记录路网日期或 unknown。
多圈层结果验证单调嵌套但不自行“修好”供应商错误；坏几何拒绝或带明确修复记录。
统计面积使用合适投影或测地法，不能直接把 EPSG:4326 平面面积当平方米。反经线、极区、超大范围设支持边界，超出时明确拒绝。
边界上设施使用 covers/within 等事先定义的规则；不能在不同 provider 适配器内偷偷变化。

### D. 人口与区域统计
选择官方数据版本 -> 验证文件与元数据 -> 读取指标和缺失码 -> 原生 CRS 下构造/读取网格 -> 区域相交 -> 按显式方法汇总 -> 标注估计与覆盖。
完整落入网格直接汇总，部分网格可按面积估计；方法可选择但必须固定到快照。比率不能直接求和，必须按有效分子/分母重新汇总；只有分类区间时不得制造精确人数。
多地点联合覆盖先构造联合区域再统计，不能累加各地点总数。
原始 Zensus 网格与分析缓存不放 git；样例用合成网格或明确获准的小文件。
BKG 地点行政归属必须展示比例尺与有效时间，边界附近不承诺门牌级准确。

### E. 时间与公交
营业时间解析传入原始 OSM 表达式、当地时间、时区、已确认假日地区/坐标上下文；不支持/缺失上下文为 unknown。
GTFS 静态 feed 先验证再分析；日期超出有效期为 unsupported/not_available，不猜测当天班次。
R5py 矩阵 travel_time 按所锁版本的输出单位转换为核心秒值；Isochrones 的 TimeDelta 单独按持续时间转换。无路径、NaN、缺失值保持缺失并说明原因，不能转换成零。公交还须验证所选版本的到达/出发时间能力；矩阵方向正确不代表已支持 arrive-by。
R5py 单独作业环境预置兼容 JAR 和数据，不在业务请求首次 import 时下载。1.1.7 配套 JAR 以源声明 URL/哈希锁定，实际下载和 hash 校验是后续验收。
不任意升级为 upstream R5 latest；预置 JDK 21+，限制区域、起终点数量、作业内存和总时长。
区域人口首选 travel-time matrix 到明确网格/点的分析；保存网格分辨率、代表点策略、departure window/percentile。
等时线与面分开。线转面必须经过验证并标注近似，禁止凸包填充不可达区以得到看似完整的人口覆盖。
来源不含实时数据时，任何结果都标为计划/模型出行时间。

### F. 比较、证据、快照和模板
profile 与 template 是版本化 JSON；Pydantic 验证引用、类型、允许的覆盖项及必需/可选能力。
优先级：数据权利/调用方强制约束 > 合法显式参数 > 模板可覆盖默认 > 行业基础默认。
执行前能力检查可返回缺失主题；结果完成度按主题计算，不能因部分成功就标整体完整。
快照保存规范化有效条件、来源时间/标识、方法和配置版本；输入内容哈希只是辅助，不能代替权限与真实来源。
变化比较先判定是否可比，再比较实体/指标；JSON 排序变化不算现实变化。
地图和摘要不隐藏不确定性；禁止将“发现三家餐厅”改写为“竞争激烈”。

## 4. 网络、缓存和失败策略

统一 HTTPX 客户端管理 connect/read/write/pool timeout、连接数量、总期限、响应大小及来源配额。
对于 429 尊重 Retry-After；对允许重试的只读请求使用有上限的退避/抖动；鉴权、无效输入、许可拒绝不反复重试。
超时不能变空数组；一次请求不得超过整体预算。不要绕过公共实例限制。
endpoint 来自管理员配置白名单；防止地址链接、重定向、文件导入或代理配置访问内部网络。
只有许可允许时缓存。缓存状态需包含新鲜度、来源和权限，不能只以地点作为键；用户/租户私有结果隔离。
供应商切换需要显式策略和记录；不可跨源拼接后抹掉来源。无可用服务时仍允许本地/手工能力。

## 5. 每项选型的接入验收门

全部为待执行验收，不是本次已通过的测试。

| 门 | 验证内容 | 通过标准 |
|---|---|---|
| A01 包与兼容性 | Python 3.12、核心和每个可选组、锁定依赖 | 可独立安装；基础 import 无网络/JVM；锁、哈希和传递许可完整 |
| A02 地址 | 德国城市/郊区/乡村、变音符、缺门牌、同名地点、三语言 | 人工标注样本输出可解释精度；错误候选不自动确认；公布命中与失败明细 |
| A03 空间正确性 | 轴交换、米/度、边界、反经线、几何无效 | 在公开支持范围内符合参考结果和明示容差；超范围明确拒绝 |
| A04 POI/去重 | node/way/relation、同址两店、多来源一店、截断 | 合成关键用例无错误自动合并；结果数/覆盖/部分状态正确 |
| A05 ORS | 新域名、路线/矩阵/等时圈、无路网、限流 | 响应契约、单位、单行道路 inbound/outbound 及失败语义正确；当前完整 ToS/额度及报告使用规则有记录 |
| A06 统计 | 合成网格完整/部分重叠、缺失、保密、比率、联合区域 | 可手算校验；无重复统计；参考年份/方法完整 |
| A07 营业时间 | 跨夜、DST、德国州 PH、未知表达式 | 已支持语义与参考一致；不支持明确 unknown；不默认为 closed |
| A08 公交 | GTFS calendar/exceptions/25:00、过期 feed、矩阵与等时线 | 有效期/时区/采样语义保留；line 不当 polygon；分钟/TimeDelta 正确转秒且缺失不为零；方向及 depart-at/arrive-by 能力正确；兼容 JAR 离线可用 |
| A09 权利与质量 | 部分结果、私有修正、受限导出、来源冲突 | G-01—G-10 全覆盖；强制约束不能被显式参数覆盖 |
| A10 模板与三行业 | T-01—T-03 和 V-01—V-08 | 行业为空可用；更换场景无需核心餐厅字段；无经营评分 |
| A11 性能与安全 | 代表区域、并发、内存、p50/p95、429、依赖漏洞 | 在实施规划中确定的调用量/SLO/预算内；记录结果与接受的限制，未测不宣称快/安全 |

A02 等质量门先建立人工参考样本；不能用“返回了 HTTP 200”作为通过。具体命中率和性能目标由下一步结合消费者要求设定，调研不捏造基准。

## 6. 接入后交付物

实现规划应产出：明确依赖锁、能力/来源清单、合约与适配器、三模板 JSON、合法合成 fixtures、
来源条款与归属记录、可复现统计示例、离线与受控在线验证结果、已知覆盖缺口和发布说明。
本方案不包含新建数据库集群、常驻调度、收费订阅或生产部署授权。

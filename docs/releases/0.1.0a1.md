# 0.1.0a1 candidate verification

Status: source and package candidate, **unreleased**. No version tag, PyPI upload, consumer repository integration, live provider activation, or deployment is claimed.

Python 3.12 isolated wheel installs were tested for core, `geometry`, `providers`, and both extras; a separate isolated sdist install also passed. The installed wheel example runs without credentials or network. Contract tests check the public facade, synthetic T-01/T-02/T-03 results, an export roundtrip, and a saved v1 result envelope. The no-secret check scans archive names for credential/key/JAR and customer data patterns, and archive contents for common private-key and token shapes, with synthetic positive controls. This bounded scan is not proof that every sensitive datum would be found.

Build with `python -m build`; install the generated wheel in a clean venv. CI installs the existing Python 3.12 lock files with hashes in its test environment. The isolated wheel tests use the package's declared ranges and independently resolve dependencies, so their passing result establishes installability, not reproducibility or cross-platform hash coverage. The exact observed combined-extra resolution is recorded in `0.1.0a1-sbom.json`. No JVM, transit, statistics, database, or provider credentials are needed for base import. That file also contains the observed license inventory and audit summary; `0.1.0a1.cdx.json` is the CycloneDX 1.4 inventory produced by pip-audit. Its nonzero audit exit records advisories against the venv's pip bootstrap, not a runtime dependency. Reevaluate the final release artifact and current advisories before distribution.

Known limits: provider calls remain disabled until rights, endpoint, account quota, cost and actual coverage are verified; mock data does not validate a live provider. Population references remain disabled. MapLibre integration supplies only a GeoJSON consumption sketch. RestaurantTrafficDiagnosis integration is future work. Authorization, storage and case access are host responsibilities. A pre-release schema shape can still change before a published stable release; breaking changes require a new schema version and migration notes.

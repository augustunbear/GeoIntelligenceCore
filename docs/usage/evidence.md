# Evidence corrections, snapshots, and exports

`apply_correction(analysis, correction, scope_token)` accepts a caller-controlled opaque scope token that must match both the analysis context and correction. The caller remains responsible for authenticating the person and authorizing the case. `correct` accepts a replacement of the same record type with unchanged evidence IDs and source identity; `confirm` and `exclude` accept no replacement. `attach` requires complete Evidence records. Originals are preserved in `Analysis.originals`, and each action is appended to `Analysis.corrections`. This is an immutable analysis copy, not a shared cache update. For a changed Location, use `confirm_location` to increment its version instead.

`snapshot(analysis, purpose)` keeps only fields and evidence whose contributing sources explicitly permit **retain** for that purpose. Unknown permissions are denied. It records redactions and a SHA-256 canonical hash over the retained snapshot JSON (apart from the hash itself); it does not store excluded raw values for reproducibility. It strips the scope token from the retained view. The configured template reference remains frozen in the snapshot. The caller must save and protect the snapshot, and explicitly choose an old snapshot to reuse it.

`export_result(snapshot, format, language, purpose)` supports `json`, `csv`, `geojson` and `de`, `zh-CN`, `en`. The purpose must match the snapshot. It checks **export** rights again for every contributing source and filters denied or unknown records, including derived values with several sources. `partial` and `redactions` describe omissions. A deterministic localized summary uses only retained evidence IDs and topic counts; native names and numerical values are not translated. CSV escapes cells beginning with spreadsheet formula triggers or control characters; GeoJSON emits only retained features with WGS84 geometry. The output is a data export, not a report layout or public redistribution grant.

Rights are source-specific and purpose-specific. An allowed `retain` does not imply allowed `export`, `display`, `redistribute`, or private caching. The caller enforces storage and access controls and must not place private supplements in a shared cache. A snapshot hash is an integrity aid for retained data, not a license or a substitute for these controls.

Topic contexts retain serving provenance (provider instance, safe HTTPS endpoint and HTTP method) in a snapshot or JSON export when every topic evidence source explicitly grants the corresponding action for that purpose. This also requires a matching topic scope and at least one evidence source. The snapshot checksum includes any retained provenance. Adapters must provide public-safe instance IDs and endpoint paths. Endpoint user information, query strings and fragments are excluded.

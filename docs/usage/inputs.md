# E03 offline map and boundary inputs

`parse_map_link(url)` recognizes only HTTPS `openstreetmap.org` or `www.openstreetmap.org` root links with exactly one `mlat` and one `mlon` marker parameter. An optional `#map=zoom/latitude/longitude` must agree with the marker. Coordinates are WGS84 and returned as longitude, latitude. Zoom-only map views, short links, unknown parameters, redirects, non-HTTPS links, alternate hosts and embedded credentials are not parsed. Parsing never makes a network request or confirms a Location; the caller still needs explicit confirmation and evidence.

`import_region(document, evidence, *, purpose="analysis")` imports one local GeoJSON Feature with Polygon or MultiPolygon geometry. The Feature properties must provide nonempty `id`, `version`, `source_ref`, `reference_period`, `crs: "EPSG:4326"`, and a positive `scale_denominator`. Source and reference period must match the supplied Evidence. Evidence must explicitly grant `use` for the requested purpose; unknown or denied rights fail closed. Import does not grant retention, cache, display, export, or redistribution. The caller must enforce those separate rights.

The importer checks existing local geometry rules, including valid rings, WGS84 coordinate ranges, no antimeridian crossing or latitude beyond 80°, a maximum 20° longitude and latitude span to exclude ambiguous nonlocal geodesic area, and fixed ceilings of 5,000 vertices and 1,000,000 km². No CRS transformation, source download or third-party provider access occurs. A successful import carries the evidence and a `boundary_precision` issue: a polygon edge is not automatically an exact legal or parcel boundary. CRS, period and scale are copied into the Result context, but the declared scale is not a proven accuracy. No real administrative dataset or its license has been approved here.

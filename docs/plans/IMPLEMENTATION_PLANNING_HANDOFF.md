## 拆分时必须交付的内容
对每一个工作项写清：工作项编号、关联 F/G/T/V 编号、用户可见目标、范围及非范围、前置依赖、输入输出、异常与回退、数据/权利前提、验收场景和验证方法。
实施规划阶段再确定模块位置、具体接口、文件、测试、技术选择与发布方式；本次不预填假实现。
建立需求到工作项到验收的追踪表，保证 F-01—F-13、G-01—G-10、T-01—T-03、V-01—V-08 均有去向。
每项可标为首批、后续或受数据条件阻塞，并说明理由。不能因暂不实现就删除目标需求。

## 必须先厘清的规划问题
| 事项 | 规划中必须给出的结果 |
|---|---|
| 首批交付范围 | 明确可独立使用的能力闭环；不默认一次实现全部目标 |
| 餐饮分类 | 来源类别映射、未知/多标签/重复情况与版本规则 |
| 三模板细则 | 必需与可选主题、默认范围依据、用户覆盖、冲突处理和结果完整性 |
| 资料覆盖 | 每项来源的国家/地区/语言/年份/精度/权利/成本与缺口 |
| 时间和区域 | 时区、边界纳入、网格分配及不可比判断 |
| 数据语义 | 区分缺失、零值、来源冲突、部分结果、不支持条件 |
| 可复现 | 地点、配置、模板、数据、方法版本和允许保存内容 |
| 责任分界 | 核心、可选适配、调用方分别承担界面、持久化、调度与权限的哪些责任 |
| 旧文档协调 | 更新路线图和契约草案，保留真实状态、不把文档当实现 |

没有现成答案的问题先查仓库和资料；普通可逆技术选择由实施规划给出建议。
付费数据、明显扩大范围或改变已确认边界，应单列决策，不默认获得授权。

## 验收组织要求
正常路径、歧义地址、错误坐标、来源失败、限流、重复地点、缺失人口、边界局部重叠、受限导出、不可比条件、人工修正和模板升级均应有对应场景。
三个行业场景用于发现不当假设，不要求三个生产级配置。
用合成/获准数据验证；精确数据源、当前服务限制和使用许可在采用前重新验证。

## 规划完成判据
- 目标目录无遗漏，每项明确交付归属或延期/数据依赖原因。
- 工作项足够具体，可独立验收且依赖无循环。
- 最小能力不被行业配置强制绑住。
- 没有静默降级、虚假零值、业务因果或无依据综合评分。
- 不混淆研究、文档、实现、测试、发布与部署。
- 提供更新后的实施文档与明确待决事项；实际开发授权另按用户指令处理。

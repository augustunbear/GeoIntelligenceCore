# GeoIntelligenceCore 完整功能设计基线

日期：2026-11-04。文档版本：1.0。本文定义目标行为，不表示功能已经实现，不规定技术方案、交付顺序或工期。
用户已确认：保持通用核心，用餐饮、零售、教育检查通用性，首先提供餐饮类别与用途模板。本文同时纳入设计审查提出的职责边界。
完整能力目录是下一步规划的输入，不等于全部功能必须进入首个版本；依赖数据的功能不能在数据不可用时承诺覆盖。

关联：[设计决策](../architecture/adr/ADR-0002-generic-core-industry-profiles.md)；[规划交接](../plans/IMPLEMENTATION_PLANNING_HANDOFF.md)。

## 1. 目标与边界

输入经过确认的地点或区域、时间与分析条件，输出可追溯的地理事实、空间计算、区域统计与质量说明。
服务餐厅诊断、价格情报、选址及未来行业产品。核心不判断经营因果、直接竞争、经营优劣、收入或收益，不生成任意综合分数。
餐饮是首个配置场景，不是核心数据模型的前提。零售和教育仅用于验证通用性，不授权同时建设完整行业产品。

| 层次 | 责任 |
|---|---|
| 通用核心 | 地点、范围、交通、设施、统计、去重、证据、比较、变化识别和结果表达 |
| 行业配置 | 类别映射、相关主题、默认条件、展示分组、所需能力声明 |
| 用途模板 | 组合通用能力，引用行业配置，表达本次任务所需输入与输出 |
| 调用方 | 地图与表单界面、账户与案件权限、存储、任务调度与通知、业务解释及决策 |

单项能力不要求行业。配置与模板可以共用但独立标识和版本化。行业推理若未来有复用需求，应另定义模块，不能藏进配置。

## 2. 共同规则 G

- G-01：事实记录、计算结果、估计结果、未经核实信息分开表达；未知不等于零。
- G-02：位置匹配精度、来源可信程度、覆盖完整程度、时间新鲜程度、计算不确定性、人工核实状态分别表达，不混成一个可信度。
- G-03：每个重要结果绑定地点版本、范围、时间条件、实际参数、来源与资料时间、方法、质量和使用限制。
- G-04：配置和模板默认值可查看、可覆盖；保存版本及覆盖后的有效条件，模板升级不改写历史分析。
- G-05：不静默改变语义。步行范围失败不能伪装成直线范围；来源切换、年份变更或分类差异必须显式说明。
- G-06：部分主题失败不丢弃其他主题结果；无结果不等于现实世界不存在。
- G-07：展示与导出遵守来源使用权限，权限未知不视为无限制。复现只在合法保存的输入与资料范围内承诺。
- G-08：德语、中文、英语说明保持事实一致；地名、机构名与来源原文保留。单位、坐标、时区和边界语义明确。
- G-09：私有补充资料与公共事实分开；人工修正保留原始记录、依据和适用范围，不自动覆盖其他客户的数据。
- G-10：地理事实不自动成为业务结论；业务判断与证据来源保持可区分。

## 3. 完整功能目录

### F-01 地点输入、识别与确认
输入完整或部分地址、邮编、名称、坐标、地图选点或受支持的地图链接。
提供候选搜索、联想、反查地址、结构化地址、行政归属、多语言名称与匹配精度。
区分建筑中心、商户地点、顾客入口、停车入口与粗略街道/城市位置，支持多个入口及适用交通方式。
候选歧义需要调用方选择；手工选点是独立回退路径。记录确认方式、时间与依据。
位置调整形成新版本，提示受影响分析需要重算，保留历史。
验收：同名商户不默认选第一项；缺门牌号不声称精确到入口；无法搜索仍可人工确认；行业为空可完成操作。

### F-02 分析范围与空间关系
支持直线范围、步行/骑行/驾车可达范围；公共交通范围以可用班次和出发时间为条件。
支持行政边界、自定义区域、多地点联合范围、多圈层、交集、合并、差集、重叠与排除区域。
记录边界来源与版本、交通条件、设施纳入规则；明确中心点、入口和边界相交等规则的差异。
支持命名与由调用方保存复用；验证无效几何、过大范围与跨区域边界。
验收：河流/铁路障碍下直线范围不被标为步行可达；跨边界设施按已声明规则统计；联合覆盖不重复计数。

### F-03 交通与可达性
输出路线距离、预计时间、交通方式、起终点入口、适用日期或时段、已知限制。
展示站点、路线；仅有合适资料时提供班次、换乘、运营时段与临时交通变化。
停车资料包括位置、到入口步行距离，容量/收费/实时空位按可用性分别提供。
无障碍、骑行条件、道路障碍、施工与通道信息均附资料范围和有效期。
验收：附近有站点不推断班次频繁；有停车场不推断有空位；一般步行路线不声称儿童安全或无障碍；静态路线不标为实时。

### F-04 周边地点与设施
通用类别涵盖餐饮、零售、办公商务、教育、医疗照护、住宿旅游、文体娱乐、公共服务、交通停车、开放空间。
每个地点可包含名称、别名、位置、地址、类别、开放状态/时间、距离/路线时间、官网与允许使用的公开联系信息。
支持分类、范围、时间和状态筛选；保留原始来源类别和归一化映射依据。
关联多来源和疑似重复记录，支持人工确认、补充、排除、停业与迁址历史。
验收：同址不同商户不错误合并；同店多条记录不重复计数；检索数量不冒充区域全部数量；没有开放时间时不判断营业中。

### F-05 企业与工作环境
区分法律主体、注册地址、总部、分支机构与实际营业/办公地点。
提供行业分类、园区与办公设施；有可信来源时提供地点适用的员工规模区间、办公时段和有效期。
按区域汇总企业地点、行业构成及规模资料覆盖率。
验收：公司总人数不分配给单一网点；注册地址不自动代表工作地；企业数量不转成工作人口或午餐需求；未知规模不计为零。

### F-06 人口、家庭与区域统计
支持可用的人口规模、密度、年龄结构、家庭、住房；就业通勤、收入购买力仅在适用且获准的数据存在时提供。
按分析范围汇总，标注原始网格/行政单元、参考年份、单位、分母、资料精度和边界分配方法。
明确完整汇总、按面积估计、中心点分配等方法差异；单独处理缺失、保密、抑制值与局部重叠。
跨年比较检查定义与空间边界是否可比。
验收：历史人口不写成当前实况；按面积分配标为估计；缺失网格不计零；居民、工作人口、游客和现场人数不直接相加。

### F-07 时间场景与实测人流
表达日期、工作日/周末、时段、季节、活动期间及路线出发时间；记录地点时区。
仅向支持时间条件的主题应用条件，不将年度人口解释为某时段现场人数。
接收合法人工/设备观测，记录地点、覆盖范围、起止时间、方向、计数对象、单位、方法、缺测、误差与去重情况。
验收：人次不冒充人数；不同观测时长不可直接比较；环境指标不生成实测人流；此能力不包含购买或部署传感器。

### F-08 多地点比较与覆盖
按一致条件比较设施、交通、人口、企业、覆盖重叠和数据质量。
比较前检查范围、时间、分类、来源覆盖、统计年份和方法；不一致时标注不可比或限制比较。
支持多门店联合覆盖与空白区域；所谓空白限定为指定范围和数据覆盖下的结果。
验收：重叠人口不重复累加；不能用数据不足地点的零值生成排名；核心不推荐最佳地点或投资收益。

### F-09 历史变化与监测结果
比较同一地点/区域的分析快照，识别新增/消失记录、状态/开放时间变化、交通和统计更新。
分开表达已核实的现实变化、来源记录变化、分析条件变化。
支持关注对象、主题与变化条件的表达；执行日程、消息发送与用户通知偏好由调用方承载。
验收：本次未检索到不等于停业；方法变化不当成环境变化；位置/范围变化时解释比较限制。本文不创建定时任务。

### F-10 证据、质量与人工核实
每个结果绑定来源引用、参考/观测/有效/获取时间、方法、查询范围、覆盖限制、权利与核实状态。
支持确认、修正、排除、附加合法证据、冲突保留及理由；保留原记录。
同一指标来源不一致时提供冲突说明，不无依据平均或选取。
验收：摘要中的重要事实能追溯；位置准确不代表数据完整；修改保留前后关系及作用范围。

### F-11 能力可用性、异常与恢复
表达未查询、未启用、未配置、不支持地区/条件、暂不可用、额度受限、部分完成、无匹配、数据冲突、有效零值及无效输入。
这些是目标业务语义，不表示现有 V1 草案已具有所有字段或枚举。
提供允许的下一步：改范围、显式换来源、用获准保存的旧资料、人工补充、重试或接受部分结果。
验收：调用方可解释为何缺失；重试不重复计数；旧资料明确标龄；替代来源不能暗中改变分类/范围口径。

### F-12 结果展示与交付
提供分析说明、重要事实摘要、地图图层、分类明细、统计方法、比较结果、来源清单及待核实事项。
支持结构化结果、表格、地理范围/图层、可引用摘要和固定时间快照，具体格式由实施规划决定。
核心提供展示所需内容，交互地图、报告排版、下载交付等由调用方或可选独立适配层负责。
验收：三语言含义一致；摘要不超出证据；受限字段不被导出；没有依据时表达无法判断。

### F-13 配置、模板与使用控制
可配置地区、语言、主题、交通方式、范围、分类、来源选择、新鲜度、核实要求、费用/额度上限及输出内容。
调用方强制限制和数据权利约束优先于所有分析参数，包括本次显式参数。在这些约束内，本次显式参数优先于模板的可覆盖默认值，行业基础默认值最后适用。
无效或互相冲突的条件明确报错，不静默忽略。能力缺失按必需/可选条件报告失败或部分结果。
验收：不指定行业可调用核心；配置不得含经营结论；实际条件与版本可回看；私有资料不跨客户泄漏。

## 4. 首个餐饮配置与三个用途模板

餐饮类别建议包括餐厅、咖啡馆、酒吧、快餐与外卖相关经营地点，保留多标签和未知类别。
相关设施可选办公商务、住宿旅游、教育、零售、交通停车等。具体标签映射需在实施规划中结合数据验证。
经营类型未知时不可擅自归为商务午餐或大型自助餐厅。餐饮配置不附统一半径或通用“竞争压力”阈值。

| ID / 模板 | 输入 | 组合输出 | 条件与边界 |
|---|---|---|---|
| T-01 餐饮周边环境 | 已确认地点、选择主题、各主题范围、时间条件 | 设施、交通、人口、企业及证据缺口 | 主题可选；不同范围分别标明；不诊断客流原因 |
| T-02 餐饮商户发现 | 位置/区域、类别、筛选条件 | 去重后的商户候选、距离、来源与覆盖说明 | 候选不等于竞争对手；不采集或推断价格策略 |
| T-03 餐饮地点比较 | 多个已确认地点、同口径指标和条件 | 指标差异、覆盖关系、可比性说明 | 不自动优劣评分或推荐投资地点 |

模板应声明所需能力及必需/可选主题；确切必需项和默认范围在下一步规划时逐项说明依据。
缺少人口数据可以保留设施结果，但不能把区域画像标为完整。调用方可选择只执行单个主题。

## 5. 通用性验收场景 V

| ID | 场景 | 要验证的共同能力 | 禁止的行业假设 |
|---|---|---|---|
| V-01 | 餐厅顾客入口、商店入口、学校多个入口 | 地点与入口独立于行业 | 所有实体必须是 restaurant |
| V-02 | 餐厅步行/驾车、零售商圈、学校通学 | 范围与通行条件可组合 | 行业固定半径；普通路线代表儿童安全 |
| V-03 | 三行业查不同类别 | 类别配置与来源映射 | 学校只能作为餐厅附属设施 |
| V-04 | 餐饮居民资料、零售家庭资料、教育年龄资料 | 通用指标与来源覆盖 | 儿童人口等于招生需求 |
| V-05 | 午间、营业时段、上下课时段 | 时区与时间支持声明 | 年度人口自动转成时段人流 |
| V-06 | 三行业多地点比较 | 一致口径与质量检查 | 自动推荐最佳地点 |
| V-07 | 未指定行业查询地址/距离/人口 | 核心可独立使用 | 必填餐饮参数 |
| V-08 | 来源失败、缺失人口、范围替代 | 明确状态与显式选择 | 缺失为零、静默换直线范围 |

验收使用合成或获准资料，不需要同时建设零售/教育配置产品。

## 6. 完整使用过程与责任

1. 调用方收集输入，核心返回候选与精度；用户确认地点/入口。
2. 选择单项能力或行业配置和用途模板，明确主题、范围和时间。
3. 检查资料覆盖、能力、已知使用限制和额度；显示缺口。
4. 分主题执行，保留部分结果与明确状态。
5. 调用方展示地图、列表和待核实项；核心接收有依据的核实记录。
6. 形成可保存的分析快照，由调用方管理访问和持久化。
7. 业务系统结合自己的资料解释结果；需要时重新分析或比较快照。

成功结果必须既说明“获得了什么”，也说明“哪些资料不能支持判断”。

## 7. 功能依赖与规划边界

依赖关系是逻辑依赖，不是本次交付排期：
F-10/F-11/G 规则贯穿所有模块；F-01 为地点分析提供起点；F-02 为 F-03/F-04/F-05/F-06 提供范围；
F-07 为支持时间的主题提供条件；F-08 依赖可比的单点结果；F-09 依赖版本化快照；
F-12 汇总合法结果；F-13 组合能力并支撑 T-01/T-02/T-03。
规划应允许单项功能独立使用，不要求为了地址搜索先实现全部能力。
企业规模、公共交通时间范围、购买力、无障碍、实时交通与人流等均为数据条件能力；下一步须明确数据来源与适用性，不因写入设计就视为已获数据。

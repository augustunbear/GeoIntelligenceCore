Store evidence in a restricted location and link its path here, never store credentials or customer data in git. A public site listing is not an account-specific grant.

Freeze route/isochrone directional cases (including one-way streets), known no-route, POI region/category and independent reference counts; predeclare pass thresholds for recall, ambiguity, failures, p50/p95, memory and cost from the actual consumer. ## Execution gate

`GEO_LIVE_TESTS=1` is necessary but insufficient. Each provider requires all frozen inputs and its own approved environment configuration. Missing any item means `blocked` in the report and a pytest `skip` for live tests; a skip is never a pass. Never infer zero-price from a general free tier without an applicable account record. Use the finite gateway budget and count retries/redirects. Record request IDs and redacted raw responses/headers, calls, billable attempts, p50/p95, peak memory, result quality, provider quota observations and status by gate. Stop at any hard limit. Do not send private/customer coordinates without purpose/privacy clearance.

The opt-in gate reads a restricted JSON file named by `GEO_LIVE_ACTIVATION_FILE`, keyed `photon`, `overpass`, `ors`, with `approved: true`, approved origin/owner/version, terms/rights/quota/pricing references, purpose, sample/threshold references, finite call/concurrency/deadline/response/cost ceilings and `credential_env` naming a set runtime variable. Do not place the file, credentials or real labels in git. Current live tests skip if opt-in or any input is missing; if a complete record appears, they deliberately **fail** until independently reviewed measured runners exist. They cannot yield a live pass in this PR.

Execution paths after approval: Photon runner must exercise search and reverse through `PhotonResolver`/`HttpGateway`, compare the pre-labeled six German strata with candidate identity, precision, ambiguity and failure expectations, and store redacted result evidence. ORS runner must exercise route, directed matrix and inbound/outbound isochrone adapters on frozen one-way/no-route cases, checking units/geometry/status. Overpass runner must query predeclared bounded regions/category sets via `OverpassPlaceProvider`, compare an independent POI reference and record remarks/truncation. All runners need capped attempts including retries, observed calls versus budget, latency and peak memory, and recorded source/version/rights; none is implemented or claimed measured here.
